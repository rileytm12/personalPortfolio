Autonomous UAV simulation & control

A first-principles 6-DOF quadrotor simulation with cascaded control, quintic trajectory generation, and a full-state error-state EKF that fuses IMU, GPS, and magnetometer to estimate position, velocity, attitude, and IMU biases — the same architecture used by PX4 and ArduPilot.

Overview

This project develops a high-fidelity quadrotor (UAV) simulation from first principles, focused on control system design, trajectory generation, and full-state estimation. The system models full 6-DOF rigid body dynamics using a quaternion-based attitude representation and simulates real-time vehicle response to control inputs and disturbances.

The architecture evolves beyond simple setpoint stabilization into a structured autonomous flight stack. Rather than commanding discrete position targets, the system generates smooth, time-parameterized trajectories (position, velocity, acceleration), enabling dynamically feasible motion.

To better reflect real-world UAV systems, control is performed on an estimated state rather than ground truth. An error-state Extended Kalman Filter (ESKF) fuses noisy accelerometer, gyroscope, GPS, and magnetometer measurements to recover the full vehicle state — position, velocity, attitude, and IMU biases — using the same architecture found in PX4’s ekf2 and ArduPilot’s EKF3.

The overall goal is to mirror real UAV flight software by explicitly building each layer—from dynamics and estimation to control and planning—within a modular and extensible architecture.

My work on the project

Dynamics modeling

  • Developed a full nonlinear quadrotor dynamics model in Python, capturing coupled translational and rotational motion.
  • Implemented quaternion-based attitude representation to avoid singularities, with conversion to Euler angles for control interpretation.
  • Built a custom numerical integrator to propagate system state, enabling stable simulation under aggressive maneuvers and disturbances.

Cascaded control system design

Designed and implemented a multi-layer UAV control architecture:

  • Outer loop (position): computes desired accelerations from trajectory tracking error.
  • Inner loop (attitude): tracks desired roll, pitch, and yaw using PID control to generate body torques.

Position control follows a feedback + feedforward structure:

acmd = Kp(xdes − x) + Kd(vdes − v) + ades

Desired accelerations are mapped to attitude and thrust commands:

ax → θdes (pitch)

ay → φdes (roll)

az → thrust

This enables tracking of dynamically consistent trajectories rather than static setpoints. All controllers consume the EKF’s estimated state — not ground truth — so they must remain stable under estimator noise, lag, and bias residuals, the same way they would on real hardware.

State estimation (Error-State Extended Kalman Filter)

Implemented a full error-state Extended Kalman Filter (ESKF) that estimates the entire vehicle state from noisy IMU, GPS, and magnetometer measurements — the same architecture used by production flight stacks.

Nominal state (16 elements):

[ p (3),   v (3),   q (4),   bg (3),   ba (3) ]
  • p, v: position and velocity in the world frame
  • q: orientation quaternion (Hamilton, body → world)
  • bg, ba: gyroscope and accelerometer biases (body frame)

Error state (15 elements):

[ δp,   δv,   δθ,   δbg,   δba ]

The attitude error δθ is parameterized as a 3-vector rotation perturbation, keeping the linearized covariance update on a true vector space and away from the unit-norm constraint on the quaternion. After each measurement update, the error correction is “injected” into the nominal quaternion via a small-angle multiplication and the error state is reset to zero.

Prediction (IMU-driven, 100 Hz):

  • Accelerometer reads body-frame specific force f = R(q)T(aworld − gworld) + ba + na
  • Gyroscope reads body-frame angular rate ω = ωbody + bg + ng
  • Bias-corrected IMU drives both nominal-state propagation and the linearized covariance step F P FT + Q

Measurement updates:

  • GPS (10 Hz): observes world-frame position; corrects p directly and bias / attitude indirectly through cross-covariance
  • Magnetometer (50 Hz): observes a body-frame heading reference mbody = R(q)T mworld, with Jacobian ∂h/∂δθ = R(q)T[mworld]×
  • Joseph-form covariance update on every step for numerical robustness

The magnetometer is what makes yaw observable. With GPS + IMU alone the gyro z-bias is unobservable, so yaw drifts unboundedly; adding a horizontal heading reference locks down yaw, exposes the gyro z-bias, and lets attitude integrate cleanly — a chain that cascades into better velocity and position estimates.

Performance (closed-loop, with realistic IMU bias and noise):

  • Position RMSE: ~0.09 m   (vs ~0.30 m raw GPS noise)
  • Velocity RMSE: ~0.07 m/s   (no direct velocity sensor)
  • Attitude RMSE: roll 0.7°, pitch 0.2°, yaw 0.25°
  • Gyro-bias estimates converge to within ~5% of injected truth on all three axes
  • Accelerometer-bias ba,z converges fastest (gravity excites it in hover); horizontal components converge during commanded translations

Visualization (10 figures) includes 3D trajectory, position / velocity tracking, attitude vs time, position and velocity error vs time with raw sensor and EKF ±3σ bounds, attitude error vs time, and bias-estimate convergence overlaid on the (known) injected truth biases.

This shifts the system from full-state feedback to estimate-driven control, aligning with real-world flight systems.

Trajectory generation & waypoint navigation

Extended the system from point-to-point control to trajectory-based autonomous navigation.

Implemented quintic polynomial trajectory generation between waypoints, ensuring continuity in position, velocity, and acceleration. Generated time-parameterized trajectories x(t), v(t), a(t).

Designed a waypoint manager that advances based on proximity thresholds and resets trajectory timing for each segment. Introduced time-scaling based on distance and dynamic constraints to ensure smooth, physically feasible motion.

This eliminates acceleration discontinuities and significantly improves tracking performance and realism.

PID control & tuning

Implemented reusable PID controllers for all translational and rotational axes. Tuned gains to achieve fast disturbance rejection, minimal oscillation, and stable trajectory tracking under wind disturbances.

Debugged and resolved:

  • Acceleration spikes from discontinuous references
  • Coupling between translational and rotational dynamics
  • Instability from aggressive trajectory timing

Software architecture

Refactored the project into a modular structure inspired by real UAV flight stacks: 

6DOF_Drone_Sim/
├── drone_main.py                       # simulation loop, logging, plotting
├── dynamics_fun.py                     # 6-DOF rigid body dynamics (quaternion)
├── integrator_fun.py                   # numerical state integrator
├── disturbances_fun.py                 # wind / gust disturbance model
├── controllers/
│   ├── outerLoop.py                    # position control + waypoint manager
│   ├── innerLoop.py                    # attitude control (roll, pitch, yaw)
│   ├── trajectoryGeneration_fun.py     # quintic polynomial trajectory generator
│   └── PID.py                          # reusable PID class with anti-windup
├── estimators/
│   ├── sensors_fun.py                  # GPS, accelerometer, gyroscope, magnetometer
│   ├── EKF_full.py                     # 16-state ESKF (position, velocity, attitude, biases)
│   └── KF_translation.py               # legacy 6-state KF (translational only, archival)
└── transform/
    ├── quat2euler_fun.py               # quaternion → Euler angles
    ├── euler2quat_fun.py               # Euler angles → quaternion
    ├── body2global_fun.py              # body → world frame rotation
    ├── angularAccel_fun.py             # rotational dynamics (Euler’s equation)
    └── Tcalc_fun.py                    # mixer: total thrust + torques → rotor thrusts

Separated dynamics, estimation, control, and trajectory generation into independent modules with clean interfaces. Maintained persistent controller and estimator states across simulation steps.

This structure improves scalability and reflects real-world systems such as PX4 Autopilot and ArduPilot.

Integration & testing

Validated end-to-end system performance through simulation:

  • Stabilization from large initial disturbances (e.g., 45° roll/pitch).
  • Smooth waypoint traversal using quintic trajectories.
  • Robust tracking under wind and gust disturbances.
  • Closed-loop control on EKF-estimated state (no truth feedback).
  • Estimator validated via position / velocity / attitude RMSE and ±3σ covariance bounds.
  • IMU bias-estimate convergence verified against the (known) injected truth biases.
  • Magnetometer-aided yaw observability confirmed by ablation: removing the mag update collapses yaw RMSE from ~0.25° back to >20°.

Used data visualization (Matplotlib) to analyze trajectory tracking, control effort, transient response, and estimator behavior. A subtle IMU/control timing bug — sampling the gyro before truth integration introduced a one-step lag in the body-rate hand-off, destabilizing the inner loop on aggressive maneuvers — was caught through targeted instrumented runs and fixed by sampling a fresh post-integration gyro reading specifically for the controller.

Results & lessons learned

  • Time-parameterized trajectories (not raw waypoint setpoints) are essential for stable, dynamically feasible flight.
  • Feedforward acceleration from the trajectory generator significantly reduces controller workload and improves tracking.
  • The error-state form of the EKF keeps attitude perturbations on a clean vector space and avoids fighting the unit-norm constraint on the quaternion.
  • Driving the EKF with raw inertial measurements (specific force + angular rate) rather than pre-conditioned acceleration mirrors real flight stacks but exposes timing and convention pitfalls — quaternion convention, perturbation side, IMU sample timing, and controller hand-off must all line up end-to-end.
  • Yaw is unobservable from GPS + IMU alone. A heading reference (magnetometer here, velocity-direction in fixed-wing) is required, and adding it cascades into better gyro-bias, attitude, velocity, and position estimates.
  • IMU-bias observability is asymmetric — each bias component converges only as fast as that axis is excited (vertical accel bias in hover, horizontal accel bias during translation, gyro biases via yaw / mag updates).
  • Cascaded control provides modularity, but each layer has to be robust to the noise and lag of the layer below it. Tuning that’s clean against truth-state feedback is not automatically clean against estimator-state feedback.
  • Clean module boundaries (dynamics ↔ sensors ↔ estimator ↔ control ↔ trajectory) made it possible to swap a 6-state translational KF for a 16-state ESKF without touching the controllers.
